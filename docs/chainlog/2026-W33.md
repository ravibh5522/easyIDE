## 2026-08-10 18:05

- **Fixed the ANR** reported as "crashing on unsupported command". It was not an exception: logcat showed `ANR in dev.tabcode.app` then `app died, no saved state`. The terminal appended output **one line at a time**, each line its own state update and recomposition, so any chatty command produced thousands of recompositions and hung the main thread. - **`sudo` now works** — a pass-through shim is written into the rootfs, since proot already runs as uid 0 and a setuid `sudo` cannot work under proot. Verified on device: `sudo whoami` returns `root`.
- **Images are cached device-wide** (`<files>/images/<image-id>.tar.gz`) instead of per environment, so a second environment from the same image needs no download. Cache key derives from the image URL's filename.
- **Guest defaults are re-applied on every launch**, so the pre-existing environment picked up the sudo shim without reinstalling — which is how the `sudo` verification above passed on an environment provisioned by an earlier build.
- **A default sandbox environment can be chosen in Settings** (star icon per environment, tap again to clear) and is pre-selected when creating a project; a default pointing at a deleted environment is ignored.

Requires `lib*.so` naming, `android:extractNativeLibs="true"` and `useLegacyPackaging = true`; `libtalloc.so.2` stays an asset reached via `LD_LIBRARY_PATH` because dlopen only needs `execute`.

## 2026-08-10 20:05

- **Terminal is now realtime and interactive.** It previously ran a command to completion, buffered all output, and printed it in one go - so a long build looked frozen and nothing could answer a prompt.
- Replaced the run-to-completion `ProcessExec` with `TerminalProcess`: it streams output as it arrives, keeps stdin open, and exposes `send()` / `kill()`. Output is delivered in **time-based batches (~60 ms)** rather than per line - per-line updates were what ANR'd on chatty commands, and per-second batching feels laggy. Nothing is accumulated in the runner, so a command that prints forever cannot exhaust memory; bounding the scrollback (500 lines) is the UI's job, which is the "auto history clean" behaviour.
- `LinuxEnvironment.run()` became `start()`, returning the live handle; `ShellRunner` and `SandboxShell` both start processes rather than waiting on them.
- The prompt now stays editable **while a command runs**: Enter writes to the running process's stdin instead of starting a new command, and the typed line is echoed locally (a child's stdin is not echoed back). A trailing partial line without a newline is also flushed, so prompts like `Password: ` appear.
- **Verified on the real tablet** (Xiaomi Pad 6, arm64, enforcing): `echo ONE && sleep 3 && echo TWO && sleep 3 && echo THREE` showed `ONE`/`TWO` on screen while `THREE` had not yet run - proof output is incremental, not batched at the end. Running `cat` and typing a line echoed it back through the process, proving stdin reaches a live command.

## 2026-08-10 23:22

- **Projects can now be saved to a user-chosen folder** (internal shared storage or an SD card), not just app-private storage. The hard constraint that shaped this: proot enters a project by bind-mounting its directory, and a bind mount needs a real filesystem path - a SAF (Storage Access Framework) tree is only reachable as a `content://` URI, so it cannot be what the sandbox actually runs against. The design that follows from that: app-private storage stays the working copy the sandbox uses; a linked folder is a best-effort **mirror** kept alongside it, additive-only (a delete/rename removes the exact path the project itself just removed - nothing scans the destination and wipes files the app doesn't recognize, which would risk deleting something the user placed there independently).
  - New `ExternalFolderSync` (sandbox-runtime, uses `androidx.documentfile` 1.1.0 - Apache-2.0, verified from the AndroidX release notes since it is a new dependency) owns every SAF call: persisted-permission lifecycle, recursive import, and per-path mirrored write/create/delete. `ProjectManager` exposes it as `mirrorWrite`/`mirrorCreateDirectory`/`mirrorDelete`/`mirrorPath`, all no-ops when a project has no linked folder so call sites never need to check first.
  - New project form gained a "Save files to" picker (`rememberFolderPicker`, pre-aimed at internal storage via `EXTRA_INITIAL_URI`); Settings gained a default-folder setting that pre-fills it. Picking a non-empty folder imports its contents as the project's starting files instead of seeding starters; picking an empty one seeds starters and mirrors them out immediately, so the folder is never left empty.

- **Settled the credential question that [decision 0009](../decision/0009-extension-platform-tiers.md) left open, as [decision 0012](../decision/0012-git-token-in-process-env-not-credential-socket.md).** The planned credential-helper daemon on a unix socket in the rootfs is **ambient authority**: every process in the sandbox can ask it for credentials, for as long as it runs, and proot gives no way to authenticate the caller.
