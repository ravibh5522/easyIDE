## 2026-09-24 14:30

- Added rollback for locally installed extensions: `LocalInstaller.rollback(id, scope, envId, approve)` re-validates the retained previous version with the install pipeline (layout, `ManifestParser`, sandbox-steps and built-in refusals, plus id/version/scope must match the dir), flips `current` atomically, records the target as current in `state.json` and keeps the version rolled back from as the new previous, so a second rollback rolls forward. Returns `Done`, `NeedsApproval` (capabilities never approved for that version; nothing changes) or `Refused` (nothing retained, built-in, not installed, invalid, revoked, I/O failure).
- `state.json` install entries gain an optional `previous{version, approvedCapabilities}`; files without it still load, and rollback then falls back to the single retained version dir with no approvals. If the process dies between the flip and the state write, the active version lists as unapproved and "back" is the recorded version with its approvals. Revocation is an injected `isRevoked` predicate (always false until M6).
- Extensions screen: "Roll back to <version>" in the detail view when a version is retained, a confirmation dialog, and the capability sheet when approval is needed. The inventory publishes the retained versions; the rescan after the flip reloads the extension.
- Why: M3 exit criterion "disable/uninstall/rollback work" (registry-and-install.md sec 10).
