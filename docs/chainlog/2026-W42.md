## 2026-10-14 12:53

- Fixed onboarding Back wiping and corrupting the Linux install. Back on any step used to cancel a running install (`OnboardingScreen.goBack`), and that exposed three more problems. (1) A cancelled install deletes its half-unpacked rootfs after it stops being active, so tapping Install again unpacked into a tree that was still being deleted. (2) The cancelled job's late `keepAlive.stop()` ended the new install's foreground service. (3) A retry reused the same environment and unpacked over whatever an install stopped mid-setup had left (a half-run apt/dpkg).
- Changes: Back now only changes the step, and the install keeps running (the rail shows it; its own Cancel still stops it). `LinuxEnvironment.install` holds a process-wide lock, so installs never overlap, including across the onboarding and Install Linux screens and on the shared image cache. `RootfsProvisioner.provision` empties the rootfs before unpacking. `EnvironmentSetupViewModel.install` waits for the previous job to finish. Regression test: `RootfsProvisionerTest` covers the leftover rootfs being replaced.
- Not covered by tests: the lock and the job ordering, because `LinuxEnvironment` and the view model need the real sandbox stack. Not verified on a device.
