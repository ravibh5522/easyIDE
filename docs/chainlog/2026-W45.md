# Chainlog — 2026-W45

## 2026-11-03 12:00

- Onboarding no longer waits for the Linux install: it runs in `BackgroundInstaller` on the application scope (moved out of `EnvironmentSetupViewModel`), the environment step offers Continue while it runs, and a slim progress bar shows on every onboarding step and, via `InstallStatusBar` in `MainActivity`, on every screen after it. The image being installed is kept in `UiPreferences` (`pending_install_image_id`) while it runs, and `EasyIdeApplication` calls `BackgroundInstaller.restore()` so a force close or Android reaping the process resumes the install at next launch (the downloader resumes its partial file; every attempt unpacks into an empty rootfs).
- Quick demo after onboarding (`ui/screens/demo`): `Demos.ALL` lists Python and Node.js one-file projects; picking one creates the project, opens the file and runs it in a root terminal (installing the interpreter first if the preset lacks it) through `DemoHandoff` and `WorkspaceViewModel.openAndRun`. Skipped when no environment exists. No HTML demo: the editor has no HTML preview yet.
- Why: a multi-minute install held the user on one screen and died with the process. Not covered by a unit test (`EnvironmentManager`/`LinuxEnvironment` are final and the module has no mocking library); compiled and existing onboarding tests pass, on-device run not done.
