# VS Code extension host - architecture and wire protocol

Decision: [0030](../decision/0030-vscode-extension-host-in-sandbox.md). Tracker: [tracker.md](tracker.md).

> **Status 2026-09-25: partly superseded by [ADR 0031](../decision/0031-vendor-vscode-extension-host.md).**
> The host is now VS Code's own extension host, vendored unmodified, and a JS main-thread adapter in the guest; there is
> no hand-written `vscode` module. What survives: the transport (JSON-RPC 2.0, Content-Length framing) and most method
> families below, re-scoped as the **adapter <-> Kotlin UI protocol**, with the amendments in
> [../vsx-compat/design-protocol.md](../vsx-compat/design-protocol.md) section P6 (`$/cancelRequest` instead of `$/cancel`,
> raw `packageJSON`, tree `getParent`/`resolveItem`, coalesced document deltas, per-instance webview origins per
> [ADR 0033](../decision/0033-extension-webview-security-model.md)). Superseded outright: the "Layout" rows for
> `services/mobile/exthost/js/src/api/*` (the `vscode` shim), `node` from `apt` ([ADR 0032](../decision/0032-node-runtime-provisioning.md)),
> "one host per environment" (one per workspace session), the shared `easyide-webview.local` origin, the phase plan
> (replaced by [../vsx-compat/roadmap.md](../vsx-compat/roadmap.md)) and "Built-in extension stubs" (vendored `vscode.git`,
> [../vsx-compat/design.md](../vsx-compat/design.md) section 7). Entry point for the program: [../vsx-compat/README.md](../vsx-compat/README.md).

```
 app (Kotlin)                                          proot guest (Node)
 +-------------------------+    stdio JSON-RPC    +--------------------------------+
 | :exthost  ExtHostMain   | <------------------> | exthost.js                     |
 |  - lifecycle, commands  |  Content-Length      |  - module loader (require)     |
 |  - main/* handlers      |  framing (as LSP)    |  - `vscode` module (our shim)  |
 | :app ports (UI, editor, |                      |  - activation, disposables     |
 |  LSP router, WebView)   |                      |  - extension code (GitLens...) |
 +-------------------------+                      +--------------------------------+
```

## Layout

| Path | What |
|---|---|
| `services/mobile/exthost/js/` | Host JS: `src/` (rpc, loader, api/*), `test/` (node --test), `bin/exthost.js` |
| `services/mobile/exthost/` (Gradle `:exthost`) | Kotlin main side: protocol types, `ExtHostMain`, handlers, ports |
| `app/src/main/assets/exthost/` | Built single-file `exthost.js` (generated by `tools/build-exthost.sh`, committed) |
| `/opt/easyide/exthost/` (guest) | Where the app copies the asset before launch |
| `/opt/easyide/extensions/<id>/` (guest) | Unpacked `.vsix` (the `extension/` dir) |

The host is launched as `node /opt/easyide/exthost/exthost.js` with cwd `/workspace` and a clean
environment (`HOME`, `PATH`, `LANG`, `EASYIDE_EXTHOST=1`; never a git token).

## Transport

JSON-RPC 2.0 over stdio, `Content-Length: N\r\n\r\n` framing, UTF-8. stderr is free text, logged
to the extension log. Requests carry `id`; notifications do not. Errors use JSON-RPC error
objects; `data.api` names an unimplemented API (`code -32601` for unknown methods,
`-32000` for an extension-visible failure, `-32800` for cancelled).
Every request from the main side may carry `params.cancelId`; `$/cancel` `{cancelId}` cancels.

Positions are `{line, character}` (0-based, UTF-16 units, as LSP). Ranges are `{start, end}`.
Uris are strings (`file:///workspace/a.ts`, `untitled:Untitled-1`, `git:...`). Guest paths only.

## Host lifecycle

1. Main starts the process, sends `host/initialize`.
2. Host replies with `{apiVersion, implemented: [names]}` and is ready.
3. Main sends `host/activateByEvent` as events occur (`*`, `onStartupFinished`, `onLanguage:x`,
   `onCommand:x`, `workspaceContains:glob`, `onView:id`, `onUri`, `onFileSystem:scheme`).
   Activation is lazy exactly as in VS Code; `activate(context)` runs once, `deactivate()` at shutdown.
4. `host/shutdown` then exit. If the process dies, main marks extensions inactive and restarts
   with backoff (3 tries, then safe-mode banner via the existing crash journal).

## Host -> main

### Commands
`cmd/register {id}`, `cmd/unregister {id}`, `cmd/execute {id, args}` (request; runs an app
command or a command registered by another extension; result json), `cmd/list {filterInternal}`.

### Window
- `window/showMessage {severity:"info"|"warn"|"error", message, items:[{title,isCloseAffordance?}], modal, detail?}` request -> picked title or null
- `window/quickPick {items:[{label,description?,detail?,picked?,id}], placeHolder, canPickMany, matchOnDescription, matchOnDetail, title}` request -> ids or null
- `window/inputBox {value, prompt, placeHolder, password, title, validate:bool}` request -> string or null. If `validate`, main sends `input/validate {id,value}` to the host per keystroke, host answers `string|null`.
- `window/progress {id, title, location:"notification"|"window"|"source", cancellable}` request start; `window/progressReport {id, message?, increment?}` N; `window/progressEnd {id}` N. Main sends `window/progressCancelled {id}`.
- `output/create {id, name}`, `output/append {id, text}`, `output/replace {id,text}`, `output/clear {id}`, `output/show {id, preserveFocus}`, `output/hide {id}`, `output/dispose {id}` (all N except create).
- `statusbar/update {id, alignment:"left"|"right", priority, text, tooltip, command, color, backgroundColor, name, accessibilityLabel, visible}` N (sent on any property change; `visible:false` hides, `statusbar/dispose {id}` removes). `text` may contain `$(icon-name)` codicon tokens; main maps the ones it knows.
- `window/setStatusBarMessage {text, timeoutMs}` N.
- `editor/show {uri, viewColumn?, preserveFocus, selection?, preview}` request -> `{uri}`
- `editor/edit {uri, edits:[{range,text}]}` request -> bool (TextEditor.edit / applyEdit).
- `editor/setSelections {uri, selections}` N, `editor/reveal {uri, range, revealType}` N.
- `decoration/createType {typeId, options:DecorationRenderOptions}` request -> {}; `decoration/disposeType {typeId}` N; `decoration/set {uri, typeId, ranges:[{range, hoverMessage?, renderOptions?}]}` N.
- `diagnostics/set {collection, entries:[{uri, diagnostics:[Diagnostic]}]}` N; `diagnostics/clear {collection, uris?}` N; `diagnostics/dispose {collection}` N. `Diagnostic = {range, message, severity 1..4, source?, code?, tags?, relatedInformation?}` (LSP shape).

### Workspace
- `workspace/openTextDocument {uri or {content, language}}` request -> `{uri, languageId, version, text}`
- `workspace/applyEdit {edits:[{uri, edits:[{range,text}]}], renames?:[...], creates?, deletes?}` request -> bool
- `workspace/findFiles {include, exclude, maxResults}` request -> [uri]
- `workspace/save {uri}` request -> bool; `workspace/saveAll {includeUntitled}`
- `workspace/getConfiguration {section, scope?}` request -> json (the host also holds a snapshot from `host/initialize` and `config/changed`; this is the fallback and the update path)
- `config/update {section, key, value, target:"global"|"workspace"}` request
- `workspace/watch {id, glob}` N / `workspace/unwatch {id}` N (main forwards `workspace/fileEvents` filtered by ids in `params.watchIds`)
- `fs/*` for non-`file` schemes only (registered by `workspace.registerFileSystemProvider`): host handles `fsp/stat|readDirectory|readFile|writeFile|delete|rename|createDirectory {scheme, uri...}` requests from main.
- `workspace/textDocumentContent {scheme, ...}` for `registerTextDocumentContentProvider`: host handles `content/provide {scheme, uri}` -> string.

### Providers
`provider/register {kind, handle, selector:[{language?,scheme?,pattern?}], options?}` request -> {}; `provider/unregister {handle}` N; `provider/changed {handle}` N (onDidChange).
Kinds and their `provide/<kind>` params -> result (LSP-shaped JSON, `undefined` -> `null`):

| kind | params | result |
|---|---|---|
| `completion` | `{handle, uri, position, context:{triggerKind,triggerCharacter?}}` | `{items:[CompletionItem], isIncomplete}`; `completionResolve {handle, item}` -> item |
| `hover` | `{handle, uri, position}` | `{contents:[markdown\|string], range?}` |
| `definition`, `declaration`, `typeDefinition`, `implementation` | `{handle, uri, position}` | `[Location\|LocationLink]` |
| `references` | `{..., context:{includeDeclaration}}` | `[Location]` |
| `documentSymbol` | `{handle, uri}` | `[DocumentSymbol]` |
| `workspaceSymbol` | `{handle, query}` | `[SymbolInformation]` |
| `codeAction` | `{handle, uri, range, context:{diagnostics,only?,triggerKind}}` | `[CodeAction\|Command]`; `codeActionResolve` |
| `codeLens` | `{handle, uri}` | `[{range, command?, id}]`; `codeLensResolve {handle, id}` -> lens |
| `formatting` / `rangeFormatting` / `onTypeFormatting` | `{handle, uri, options, range?, ch?, position?}` | `[TextEdit]` |
| `rename` | `{handle, uri, position, newName}` | `WorkspaceEdit`; `prepareRename` -> `{range, placeholder}` |
| `signatureHelp` | `{handle, uri, position, context}` | `SignatureHelp` |
| `documentHighlight` | `{handle, uri, position}` | `[{range, kind}]` |
| `documentLink` | `{handle, uri}` | `[{range, target?}]`; `documentLinkResolve` |
| `foldingRange` | `{handle, uri}` | `[FoldingRange]` |
| `selectionRange` | `{handle, uri, positions}` | `[SelectionRange]` |
| `inlayHint` | `{handle, uri, range}` | `[InlayHint]`; `inlayHintResolve` |
| `semanticTokens` / `semanticTokensRange` | `{handle, uri, range?}` | `{data:[int]}` with `legend` in options |
| `color` | `{handle, uri}` | `[ColorInformation]`; `colorPresentation` |
| `callHierarchy`, `typeHierarchy` | prepare/incoming/outgoing | LSP shapes |
| `linkedEditing`, `inlineCompletion`, `evaluatableExpression`, `inlineValue` | later | |
| `fileDecoration` | `{handle, uri}` | `{badge?, tooltip?, color?, propagate?}` |
| `timeline` | `{handle, uri, options}` | `{items}` (GitLens file history) |
| `commentController`, `debugAdapter`, `notebook`, `customEditor` | not planned | |

The main side routes each `provider/register` into the app's language-feature router next to the LSP sources (same `FeatureRouting`), keyed by selector; results from an extension provider merge with LSP results the way multiple LSP sources already do.

### Tree views
`tree/register {viewId, canSelectMany, showCollapseAll, dragAndDrop?}` request; `tree/refresh {viewId, elementIds or null}` N; `tree/reveal {viewId, elementId, select, focus, expand}` N; `tree/setMessage {viewId, message}`, `tree/setTitle {viewId, title, description, badge}`.
`TreeNode = {id, label, description?, tooltip?, iconPath?, resourceUri?, collapsibleState:0|1|2, contextValue?, command?:{command,title,arguments}, checkboxState?}`. Ids are host-generated strings unique per view; the host keeps the element map. Main renders views declared in the extension's `contributes.views`/`viewsContainers` through the R4 view schema ([../extension-sdk/views.md](../extension-sdk/views.md)); context menus come from `contributes.menus` `view/item/context` with `when` clauses.

### Webviews
`webview/create {handle, viewType, title, viewColumn, options:{enableScripts, retainContextWhenHidden, localResourceRoots:[uri], portMapping}, iconPath?}` request; `webview/setHtml {handle, html}` N; `webview/postMessage {handle, message}` request -> bool; `webview/reveal {handle, viewColumn, preserveFocus}` N; `webview/setTitle {handle, title}` N; `webview/dispose {handle}` N; `webview/registerView {viewType, options}` request (WebviewViewProvider). Main sends `webview/message`, `webview/state`, `webview/disposed`, `webview/resolve`.
Webview page contract: `acquireVsCodeApi()` provides `postMessage`, `getState`, `setState`; `vscode-webview://` style resource URLs are rewritten to `https://easyide-webview.local/<handle>/<guest-path>` served by a `shouldInterceptRequest` from the extension dir / localResourceRoots only; CSP from the HTML is kept; `asWebviewUri` returns that form; `cspSource` is `https://easyide-webview.local`.

### Terminals, SCM, storage, secrets, misc
- `terminal/create {id, name, shellPath?, shellArgs?, cwd?, env?}` request -> {}; `terminal/sendText {id, text, addNewLine}` N; `terminal/show|hide|dispose {id}`; main sends `terminal/data {id, data}` if `onDidWriteData` is used, `terminal/closed {id, exitCode}`. `Pseudoterminal` extensions: host forwards `terminal/input`.
- `scm/createSourceControl {id, label, rootUri}` -> {}; `scm/update {id, groups:[{id,label,resources:[{uri,decorations,command}]}], count, inputBox, statusBarCommands, acceptInputCommand}` N. Phase 5.
- `storage/get|update {scope:"global"|"workspace", ns:extId, key, value}` requests (`Memento`); host caches and writes through. `secrets/get|store|delete {ns, key}` requests (Android Keystore in main).
- `env/openExternal {uri}` request -> bool; `env/clipboardRead|Write {text}`.
- `log/append {extId, level, message}` N (also `console.*` from extension code, redirected by the host).
- `ext/getExtension {id}` - handled in host from ExtDesc; `ext/activated {id}` N to main for the Extensions UI.
- `telemetry/*`: dropped, `TelemetryLogger` is implemented locally as a no-op.

## Built-in extension stubs (in the host, not the app)
- `vscode.git` extension API 1 (`getAPI(1)`: `git.path`, `repositories`, `getRepository`, `onDidOpenRepository`, `onDidChangeState`; repositories report `rootUri`, `state.HEAD`, `state.remotes`, `state.refs`) backed by the guest `git` binary and `.git` watching. GitLens needs this.
- `vscode.typescript-language-features`, `vscode.markdown-language-features`: absent (extensions declaring `extensionDependencies` on them get a clear error).
- `vscode.env.remoteName` = undefined, `uiKind` = Desktop (1) so extensions take their normal desktop path; `appHost` = "desktop".

## Phases (see tracker)
1. **Host + core API**: process, loader, activation, commands, window messages/quick pick/input, output channels, status bar, workspace docs/fs/config, `context.globalState/workspaceState/secrets/subscriptions/extensionPath/storageUri`, `Uri/Position/Range/Selection/Location/Diagnostic/TextEdit/WorkspaceEdit/EventEmitter/Disposable/CancellationTokenSource/ThemeColor/ThemeIcon/MarkdownString`. Ships a hello-world pack running on the tablet.
2. **Language providers + diagnostics + decorations + code lens** (GitLens blame/annotations lens, most language extensions).
3. **Tree views + view containers + menus** (GitLens views, many others).
4. **Webviews** (GitLens Home/Commit Graph/Focus, Claude Code panel).
5. **git extension API, SCM, terminals, timeline, file decorations**.
6. **Corpus + compatibility table** (CI loads real extensions headless with a fake main; table published).
