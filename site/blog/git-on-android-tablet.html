How to use git on an Android tablet: clone, commit and push

By Ravi Kumar, lead developer · October 14, 2026

easyIDE has two ways into git, and they agree with each other: a built-in Source Control view with a history graph, and the real git in the Ubuntu terminal. A commit made in one shows up in the other.

Clone a repository

On Home, tap New, import or clone, then Clone repository, paste an https:// URL and pick the environment to clone with. Cloning works for public repositories over HTTPS; SSH keys are not available yet. For a private repository, clone it in a terminal after adding a token (below).

Tell git who you are

The first time you commit, easyIDE asks for your name and email and saves them for all projects or just this one. You can change them later in Settings > Git. Committing from the terminal instead? Set them there:

git config --global user.name "Your Name"
git config --global user.email "you@example.com"

Stage, commit, amend

Open Source Control in the activity rail. Changed files appear in a tree; stage, unstage or discard each one, write a message and commit. The commit button's menu has amend. Changes made by tools in the terminal show up here too.

Read the history

The Graph shows branches and merges with branch and tag chips, like VS Code's. Long-press (or right-click) a commit to cherry-pick it, tag it, check it out or compare it.

Push to GitHub

Pushing over HTTPS needs a personal access token. Create one on GitHub (Settings > Developer settings > Personal access tokens) with access to the repository, then add it in easyIDE under Settings > Git > Credentials. Fetch, pull and push then work from Source Control, and the ahead/behind counts stay current if you turn on Fetch automatically.

Prefer the command line?

Everything is real git:

git switch -c feature/tablet
git add -p
git commit -m "work from my tablet"
git log --oneline --graph -10

Limits today

  • No merge editor yet: resolve conflicts in the editor or the terminal.
  • Network operations have had less device testing than local ones; report problems on GitHub.
